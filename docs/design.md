# 模块设计与接入约定

## 生命周期和线程

`Gamepad` 是不可复制、不可移动的 RAII 对象，一只对象拥有一个 XInput 槽位、一条采集线程和一个队列。构造时验证配置、分配队列和打开日志，最后启动线程；构造失败抛出异常，不遗留运行线程。析构自动停止并 join，也可以提前调用 `stop()`。`stop()` 可重复、可并发调用，会唤醒轮询等待，不必等到重连间隔结束。

采集线程从不执行业务 Lambda。`dispatch_pending(handler, max_count)` 在调用线程逐条执行回调，最多消费指定数量，避免输入繁忙时饿死主循环。回调异常传回调用者，当前消息已消费，采集继续运行。不能在回调内销毁正在调用 `dispatch_pending` 的对象；所有成员调用结束前，对象必须仍然存活。

`try_pop`、`wait_pop` 和 `dispatch_pending` 共用一个 FIFO，通常选择一种消费方式。允许从不同线程调用，但消费者会分走消息，不提供广播订阅。业务应指定单一消费者以维持处理顺序。

停止时会取消仍按住的键，生成 `disconnected`（此前连接时）和最终 `stopped`，随后关闭队列。已排队的消息仍可读取；队列排空后 `wait_pop` 返回 `stopped`。`wait_pop` 的超时是相对等待时间；传负值会抛异常。析构前必须自行结束外部访问线程。

## 消息和恢复

`Event` 是固定大小的值类型，没有字符串或动态数组。每条消息包含递增序号、对象内的单调时间戳、完整当前状态、事件类别、相关按键、按住时长和取消原因。状态保留原始整数轴值及归一化后的值。

| 事件 | 含义 |
| --- | --- |
| `connected` | 后端首次成功或恢复；携带初始完整状态 |
| `button_down` / `button_up` | 采样观察到按键边沿；方向键、摇杆按下、肩键和合成扳机键都适用 |
| `short_press` | 在长按阈值之前正常释放 |
| `long_press` | 正常按住达到阈值，仅触发一次 |
| `state_changed` | 模拟轴或扳机变化，可合并 |
| `device_info_changed` | 后端能力或电池信息变化 |
| `disconnected` | 后端断开、错误或停止；状态已归零，先生成取消的松开事件 |
| `backend_error` | 原生错误，附 `native_error`；相同连续错误只发一次 |
| `stopped` | 采集结束，之后不会再入队 |

队列构造时预分配，满时在短临界区内丢弃最老消息，再插入新消息。`sequence` 在入队时递增；`dropped_total` 在出队时写入，是当时累计丢弃数量。收到序号缺口或丢弃计数增加时，应停止依赖旧的边沿推断，使用消息中的完整状态恢复。还可调用线程安全的 `snapshot()` 读取采集线程最近发布的状态。

完整状态无法恢复丢失的历史短按或长按。固定容量、允许生产者持续运行、消费者可无限期停顿，这三个条件下不能同时保证历史事件绝不丢失。需要历史完整性时，应选择足够容量并及时消费，或在业务层检测溢出后报错。停止事件也可能挤掉旧消息，遵循同一规则。

`statistics()` 提供生成、消费、丢弃、队列深度、峰值、后端读取次数、读取错误和错过轮询期限次数。队列统计内部一致；轮询计数是相邻时刻读取的原子快照，不构成全系统事务。

## 按键时序

- 默认短按阈值为 500 ms，可配置。时间来自 `steady_clock`，不是系统 UTC，不受改系统时间影响。
- 正常短按顺序为 `button_down → button_up → short_press`。
- 长按达到阈值即生成一次 `long_press`，释放后只有 `button_up`，不会补发短按。
- 若轮询跨过阈值且下一次观察到已经释放，会先生成 `long_press` 再生成 `button_up`。
- 即使 XInput 的 packet 不变，仍检查长按计时。
- 连接时已经按着的键没有已知起点，不补发按下、长按或短按；其首次释放标记为 `initially_held`，之后按正常流程处理。
- 断连、错误、停止会清理按住状态，取消的 `button_up` 不生成短按/长按。接收器若一直伪装为连接，程序只能按后端实际报告处理，不能保证发现无线链路丢失。
- 一次采样中多个按键同时变化，时间戳相同，按固定按键顺序输出。事件顺序不声称代表采样间隔内的真实物理先后。

轮询只能观察状态，不能保证捕获两次轮询之间完成的极短脉冲。时间戳是软件观察时间，按住时长同样具有采样误差。

## 模拟输入

原始摇杆保持 `[-32768, 32767]`，原始扳机保持 `[0,255]`。摇杆归一化使用径向死区并将向量长度限制在 1；原始数值不被死区覆盖。扳机归一化为 `[0,1]`。

默认每 8 ms 最多发送一次模拟变化消息，未变化不发；`analog_event_interval=0us` 关闭合并。消息是最新观察状态，不是原始报文录制。`snapshot()` 每次采集都会更新，数字按键事件不受模拟合并间隔限制。

LT/RT 同时保留独立模拟数值并合成为可长短按的逻辑键。默认值达到 30 为按下，下降到 25 为松开，滞回避免阈值附近反复跳变。

## 性能和日志

连接时默认每 4 ms 查询，支持 1 ms 至 1 s 配置；断开或错误时默认每 1 s 重试。Windows 10 1803+ 使用线程独立的高精度 waitable timer 和停止事件，不忙等，也不全局修改 Windows 定时器精度。旧系统回退普通等待计时器并记录精度告警；其他平台的核心测试使用可中断的条件变量。每次等待根据单调时钟的绝对期限计算剩余时间。错过期限后跳过追赶，避免突发空转。系统调度与驱动耗时影响实际间隔，这不是硬实时接口。

状态比较、事件构造、队列入队/出队的正常路径不需要逐消息堆分配。队列通过互斥锁保护短临界区，使生产者覆盖最老元素和消费者复制并发时仍保持一致；不把复杂的无锁覆盖算法作为未经验证的性能假设。

模块默认 warning 日志到 stderr；示例默认 info。示例在交互终端中默认使用固定面板，该模式关闭控制台日志以保护布局，但保留文件日志；错误和溢出计数在面板中显示。使用 `--events` / `--json` 时恢复控制台日志。info 包含启动、连接、断开、停止；warning 包含最多每秒一次的队列溢出累计计数；error 包含原生读取错误及内部故障。debug 当前与 info 相同，预留诊断级别，不逐条记录输入。日志文件可选，默认每份 1 MiB、最多两份备份。父目录必须存在，打开失败会使构造失败；运行时文件写入/轮转失败会禁用文件输出并尝试报告一次。

日志由采集线程同步写入，仅发生在低频生命周期/错误路径；如果日志存储特别慢，仍可能影响该次轮询，`missed_deadlines` 可观察。示例的面板更新和逐事件打印都在 main 线程。面板最多约 30 fps，只写变化值，左侧标签仅在首次绘制或终端尺寸变化时绘制；逐事件模式打印速度不足时按既定队列策略丢旧消息。默认不额外开日志线程，以减少线程和退出管理复杂度。

## 平台、设备和范围

当前原生后端为 Windows 8+ 系统 `XINPUT1_4.dll`，只使用文档化接口。能力信息和电池信息在连接时及每 5 秒刷新；电池档位仅在后端返回已知电池类型时有效，无法读取不等于没电。USB 接收器可能把无线手柄报告成有线设备。

`slot` 是当前 XInput 的 0..3 槽位，可能被别的设备占用，不是永久设备 ID。型号配置决定编译目标与参数，不证明槽位里的实体就是该型号；多手柄时显式选择槽位。模块不宣称能从标准 XInput 获取唯一序列号、全部 USB 信息、厂商功能键或传感器。原生 XInput 保留位不会作为标准按键输出。

`src/core/` 与 Windows 头文件无关，后端只需实现 `Backend::read()` 返回统一样本。Linux 迁移时新增后端并处理 Linux 的设备选择、权限和热插拔；事件、队列和生命周期可共用。当前非 Windows 构建只支持测试共用逻辑，原生 Linux 输入尚未实现。
